# 分布式通信中间件重写项目计划

## 项目概述

本项目目标是重写一套面向机器人领域的发布-订阅通信中间件，类似 ROS2 的机器人操作系统。支持进程内/进程间/跨主机的通信，统一传感器接入模型。

**技术栈：** C++17/20、CMake、Fast-DDS (原 FastRTPS)、共享内存、信号槽、图拓扑、序列化

**总工期：** 12 周（约 3 个月）

---

### 第 2 周：无锁基础组件

**目标：** 基于原子变量和 CAS 操作实现核心无锁数据结构。

| 天数    | 任务                             | 关键设计点                                                   |
| ------- | -------------------------------- | ------------------------------------------------------------ |
| Day 1-2 | **无锁队列 (LockFreeQueue)**     | 基于 Michael-Scott 无锁队列算法；多生产者-多消费者（MPMC）；`enqueue` / `dequeue` 用 CAS 循环；支持阻塞等待（结合信号量）与立即返回两种模式 |
| Day 3-4 | **无锁哈希表 (LockFreeHashMap)** | 开放寻址法 + 惰性删除；`find` / `insert` / `erase` 全部无锁；key 支持整数与字符串（用 hash 转为整数）；rehash 采用"迁移中 + 新表"双表策略 |
| Day 5   | **原子读写锁 (AtomicRWLock)**    | 读多写少场景优化；使用原子状态字，高 30 位记录读者数，低 1 位为写标志；写者饥饿保护（写等待计数 + 新读者阻塞） |

**验收标准：**
- 每个组件配套单元测试：正确性测试（单线程 + 多线程）、压力测试（高并发下无 data race）
- 使用 ThreadSanitizer 验证，零告警
- Benchmark 对比 `std::mutex` 版本，明确性能优势

### 第 3 周：序列化协议

**目标：** 设计一套紧凑、可扩展的序列化协议。

| 天数    | 任务             | 详细内容                                                     |
| ------- | ---------------- | ------------------------------------------------------------ |
| Day 1-2 | 协议设计         | 定义类型 ID 枚举（`INT8` ~ `FLOAT64`、`STRING`、`ARRAY`、`STRUCT`）；设计 wire format：`[TypeID:1B][Length:4B][Payload:N]`；大小端兼容处理 |
| Day 3   | 基础类型序列化   | `Serializer::write(int32_t)` / `Deserializer::read(int32_t)`；利用模板 + `if constexpr` 分派；string 写入时先写长度再写数据 |
| Day 4   | 复合/自定义类型  | STL 容器适配（`vector`、`map`、`optional`）；用户自定义结构体通过宏或模板特化注册：`CMW_SERIALIZABLE(MyStruct, field1, field2, field3)` |
| Day 5   | 测试与 Benchmark | 序列化正确性往返测试；与 JSON/Protobuf 对比序列化后数据大小和耗时 |

**验收标准：**
- 所有基础类型 + 3 个自定义复杂结构体的序列化/反序列化正确性测试
- 性能测试：1MB 数据的序列化耗时 < 100μs（作为性能基线）

## Phase 2: 核心系统（第 4-6 周）

### 第 4 周：日志系统

**目标：** 实现高性能、线程安全的日志系统。

| 天数    | 任务            | 详细内容                                                     |
| ------- | --------------- | ------------------------------------------------------------ |
| Day 1-2 | 核心实现        | 日志级别枚举（`TRACE` ~ `FATAL`）；`CMW_LOG(level) << "msg" << data` 流式接口；宏展开为 `LogStream` 临时对象，析构时自动提交 |
| Day 3   | 文件自动轮转    | 基于文件大小的轮转策略（`max_size` + `backup_count`）；轮转时原子切换文件句柄；支持按小时/天轮转的可选扩展点 |
| Day 4   | 动态日志级别    | 全局级别 + 按模块（tag）级别；运行时可调整，`SetLogLevel("transport", WARN)`；使用无锁哈希表存储 tag → level 映射，支持热更新 |
| Day 5   | 异步写入 & 测试 | 后台线程 + 无锁队列收集日志条目批量落盘；前端仅做入队操作，延迟可控；性能测试与完整性测试 |

**关键设计点：**
- RAII 累积写入：`LogStream` 对象持有缓冲区，析构时一次性写入队列，避免频繁系统调用
- 崩溃安全：`FATAL` 级别日志同步写入 + `fflush`

### 第 5 周：Node 模型与图拓扑

**目标：** 定义 Node 为核心抽象，用有向图管理拓扑关系。

| 天数    | 任务          | 详细内容                                                     |
| ------- | ------------- | ------------------------------------------------------------ |
| Day 1-2 | Node 核心模型 | `Node` 类：持有名称、唯一 ID、发布者列表、订阅者列表；`Node::CreatePublisher<T>(channel)` / `Node::CreateSubscriber<T>(channel, callback)`；支持生命周期管理（创建/销毁） |
| Day 3-4 | 有向图拓扑    | 图数据结构：顶点 = Node，边 = DataChannel（含 topic 名、类型信息）；邻接表存储；支持 BFS/DFS 遍历、环路检测；拓扑变更通知（Node 加入/离开事件） |
| Day 5   | 去中心化广播  | Node 加入时广播 `NodeJoin` 消息；Node 离开时广播 `NodeLeave` 消息（含优雅退出与超时检测）；每个 Node 本地维护全局拓扑视图；心跳机制检测离线节点 |

**验收标准：**
- 多 Node 拓扑构建测试：3 个 Node 形成发布-订阅链，拓扑图正确
- 动态加入/离开测试：新 Node 加入后所有节点拓扑一致

## Phase 3: 通信后端（第 7-10 周）

### 第 7-8 周：共享内存通信

**目标：** 实现高性能进程间共享内存通信。

| 天数     | 任务           | 详细内容                                                     |
| -------- | -------------- | ------------------------------------------------------------ |
| Day 1-2  | 共享内存管理   | `SharedMemory` 类：`posix` 平台用 `shm_open` + `mmap`；内存段管理（分配/回收）；引用计数管理多进程生命周期 |
| Day 3-5  | 无锁环形缓冲区 | 基于无锁队列改造为共享内存环形缓冲（`LockFreeRingBuffer`）；单生产者-单消费者（SPSC）优化路径；写入时 `memcpy`，读取时零拷贝（直接返回指针） |
| Day 6-7  | 通道管理与通知 | 每个 channel 对应一个环形缓冲区；用 `eventfd`（Linux）或 POSIX 信号量实现跨进程通知；接收端 `poll` 等待事件避免忙等 |
| Day 8-10 | 测试与性能     | 进程间吞吐量测试（目标 > 1GB/s 对于大数据块）；延迟测试（目标 < 10μs 对于小消息）；多进程稳定性测试 |

---

### 第 9-10 周：Fast-DDS 网络通信

**目标：** 实现跨主机的 DDS 通信后端。

| 天数     | 任务           | 详细内容                                                     |
| -------- | -------------- | ------------------------------------------------------------ |
| Day 1-3  | Fast-DDS 集成  | CMake 集成 Fast-DDS 依赖；封装 `DdsTransport` 实现 `Transport` 接口；Topic 类型动态注册（使用序列化协议的二进制 blob，避免 IDL 生成）；QoS 策略配置（Reliability、Durability、History） |
| Day 4-5  | 发现机制       | 利用 Fast-DDS 内置的 Simple Discovery Protocol；Node 信息映射到 DDS Participant；拓扑广播基于内置 discovery 或自定义 built-in topic |
| Day 6-7  | 回退与混合通信 | 同主机检测：对比 Node 的 `host_id`；同主机自动选共享内存，跨主机自动选 DDS；提供手动强制指定后端的接口 |
| Day 8-10 | 联调测试       | 同主机双后端对比测试；跨主机（2 台机器）通信测试；网络断开/恢复的鲁棒性测试；大消息（>10MB）分片传输测试 |

**验收标准：**
- 共享内存延迟 < 10μs（1KB 消息）
- DDS 延迟 < 100μs（局域网，1KB 消息）
- 跨主机通信稳定运行 1 小时无丢包

## 编码规范建议

1. **C++ 标准：** C++17 最低，鼓励使用 C++20 特性（`std::span`、`std::atomic_ref` 等）
2. **命名：** 类 `PascalCase`，函数 `camelCase`，成员变量 `snake_case_` 后缀下划线，常量 `kPascalCase`
3. **错误处理：** 不使用异常（考虑实时性），统一使用 `Result<T, ErrorCode>` 返回值
4. **代码审查：** 每个 Phase 结束进行 Code Review，重点关注线程安全和资源管理
5. **CI/CD：** Phase 1 即配置 GitHub Actions / Jenkins，每次提交自动编译 + 测试 + TSan 检查
