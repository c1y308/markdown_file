# 地平线

## 基础

### 数组和指针的区别

表面上它们都可以用 `[]` 访问元素，但底层机制截然不同，`a[i]` 对于数组和指针来说，都等价于 `*(a + i)`。

- 对于**数组**：`arr` 先 decay 成 `&arr[0]`，再加 `i` 解引用。
- 对于**指针**：直接使用指针的值进行算术运算和解引用；所以 `ptr[2]` 完全合法，只要指针指向合法内存区域。

#### 本质

- **数组**：一块连续内存中**一组相同类型对象的集合**，数组名代表整个数组对象。
- **指针**：一个**变量**，其值为另一个对象的地址。本身占8字节（64位）。

#### 内存布局

- `arr` 的内存：`[1][2][3][4][5]` 连续，`sizeof(arr) = 5 * sizeof(int) = 20`。
- `ptr` 的内存：一个8字节指针变量，存着 `&arr[0]`，它不包含5个整数，**未初始化时不指向有效内存**。
- **数组名本身没有独立的存储位置**（不像指针变量那样有一个地址来存指针值），**它的“地址”就是数组首元素地址**。

#### 数组名与指针

- 在大多数表达式（1.**`sizeof` 的操作数**；2.**单目 `&`（取地址）的操作数**）中，数组名会**隐式转换（decay）**为指向首元素的指针，类型变为 `int*`，但这不改变其原本的数组身份。

- `&arr` 的值和 `arr`（decay 后）数值上相同，都是首字节地址，但**类型不同**。`&arr + 1` 会跳过整个数组（移动 `5*sizeof(int)` 字节），而 `arr+1`（decay 后）只跳过1个 `int`。

- 数组名在表达式中 decay 后产生的指针值是一个**右值**（临时值），不可被赋值或自增。**指针变量是左值**，可以改变指向。

  ``` c++
  int arr[5];
  int *ptr;
  
  arr = ptr;        // 错误！数组名是常量指针语义（不可修改的左值）
  ptr = arr;        // 正确，指针变量可赋值
  
  arr++;            // 错误
  ptr++;            // 正确，指针算术
  ```

  

#### `sizeof`的天壤之别

这是区分数组和指针最直接的手段：

``` c++
int arr[10];
int *ptr = arr;

sizeof(arr);   // 10 * sizeof(int)  —— 整个数组大小
sizeof(ptr);   // 指针本身大小，64位系统为8
```

即使数组作为 `sizeof` 的操作数，也**不发生 decay**，`sizeof(arr)` 返回的是整个数组的字节数。`sizeof(ptr)` 永远返回指针变量本身的大小，与其指向的数据量无关。

#### 作为函数参数：彻底退化为指针

``` c
void foo(int arr[10])   // arr 实际上是指针，等价于 int *arr
void bar(int arr[])     // 同样是指针
void baz(int *arr)      // 明确指针

// 在函数内部：
sizeof(arr);    // 永远是指针大小，不是数组大小！
```

**C 语言从不按值传递数组**。所谓的“数组形参”只是语法糖，编译器将其调整为指针。这就是为什么需要额外传递长度。

### `volatile`的作用

`volatile`是 C 语言优化屏蔽关键字，**强制 CPU 每次读写变量都访问原始内存，禁止编译器把（1）变量缓存到 CPU 寄存器、（2）优化读写操作或（3）调整指令顺序**。

**`volatile` 只保证访问发生，不保证访问是原子的**。多任务环境下，可能读到撕裂的数据。需要原子操作时，必须用专用指令或 `std::atomic`。

#### 典型使用场景

- **内存映射硬件寄存器**（最正统的用途）：

  嵌入式开发中，硬件寄存器的值可能由外设随时更改，每次读写都有硬件含义。

  ``` c++
  // 状态寄存器（只读），控制寄存器（只写）
  #define STATUS_REG  (*(volatile uint32_t *)0x40021000)
  #define CTRL_REG    (*(volatile uint32_t *)0x40021004)
  
  void wait_ready(void) {
      while (!(STATUS_REG & 0x01));   // 必须每次都读硬件，不能优化成一次读取
  }
  
  void start_dma(void) {
      CTRL_REG = 0x01;
      CTRL_REG = 0x02;   // 连续两写代表不同阶段，必须保留
  }
  ```

- **中断服务程序与主程序共享的标志**

  任何被 ISR 修改、主程序读取（或反之）的全局变量，都应声明为 `volatile`。

- **软件延时循环**

  ``` c
  void delay(volatile int cycles) {
      while (cycles--);
  }
  ```

  参数不用 `volatile`，编译器可能认为循环无实际作用而**整个删除**，或把递减放进寄存器一次算完。

### 宏定义和内联函数的区别

| 对比维度   | 宏定义`#define`                      | 内联函数`inline`                         |
| ---------- | ------------------------------------ | ---------------------------------------- |
| 处理阶段   | **预处理阶段**做纯文本替换           | 编译阶段做语法解析、类型校验             |
| 类型安全性 | **无类型检查**，易出现运算优先级 bug | 严格校验参数、返回值类型，类型安全       |
| 作用域     | **全局生效**，易出现命名冲突         | 遵循 C 语言作用域规则，可控性强          |
| 调试能力   | 预处理后宏代码消失，**无法断点跟踪** | 可像普通函数一样断点调试                 |
| 代码膨胀   | 多次调用会生成多份冗余代码           | 编译器可按需决定是否展开，能控制膨胀规模 |

### 互斥锁和自旋锁的区别，有什么作用

#### 共同作用

二者都是 Linux 内核用于**多执行单元互斥访问共享资源、解决竞态问题**的同步工具。

#### 核心区别

- **拿不到锁的行为**

  自旋锁：原地忙循环反复抢锁，**CPU 不睡眠、不调度其他任务**；适用于**持有锁时长极短、不允许睡眠的场景（如中断上下文）**；

  互斥锁（mutex）：**线程进入睡眠状态**，主动让出 CPU，锁释放后再被唤醒竞争。适用于持有锁耗时较长、可能触发睡眠的场景，**仅能在进程上下文使用**。

- **CPU 资源消耗**

  自旋锁长时间抢锁会空耗 CPU；互斥锁会释放 CPU 给其他任务，资源利用率更高。

### 什么是进程上下文、内核线程上下文、中断上下文

上下文指 CPU 执行任务时的**寄存器、栈、内存映射等运行环境**，**任务切换时需要保存 / 恢复**：

1. **进程上下文**：用户进程**触发系统调用 / 异常进入内核态时的运行环境**，包含进程的**用户态寄存器、进程专属栈、页表**与资源；支持睡眠、进程调度、可访问用户空间内存。
2. **内核线程上下文**：内核专属后台线程的运行环境，**无用户空间，仅使用内核栈与内核页表**；支持睡眠、参与普通进程调度，典型如内存回收的`kswapd`线程。
3. **中断上下文**：硬件触发中断后执行中断处理函数的环境，不依附任何进程，没有进程页表、**禁止睡眠**、不能访问用户空间，处理逻辑必须快速完成，避免阻塞其他中断。
